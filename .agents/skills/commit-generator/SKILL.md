# /commit-generator

Analyzes staged git changes, generates a conventional commit message following the Conventional Commits 1.0.0 specification, then asks the user what to do with it (commit, commit + push, edit, or cancel).

## Usage

```bash
/commit-generator
```

Operates on staged changes only — the canonical `git add` → `git commit` flow. If nothing is staged, prompt the user to stage changes first and stop.

## Process

1. **Inspect staged changes**
   - Run `git diff --cached --stat` and `git diff --cached` to see what will be committed
   - If empty: tell the user nothing is staged and stop

2. **Classify the change**
   - Determine the appropriate commit type (feat, fix, docs, refactor, test, chore, etc.)
   - Detect scope from file paths when applicable (e.g. `api`, `ui`, `prisma`)

3. **Draft the message**
   - Format:

     ```
     <type>[optional scope]: <description>

     [optional body — bullet list of meaningful changes]
     ```

   - Display the drafted message to the user in a fenced code block

4. **Ask the user what to do** — use the `AskUserQuestion` tool with these options:
   - **Commit** — run `git commit -m "<message>"`
   - **Commit + push** — run `git commit -m "<message>"` then `git push`
   - **Edit then commit** — ask the user for their revised message, then commit it
   - **Cancel** — do nothing

5. **Act on the choice**
   - On commit: pass the message via a HEREDOC to preserve formatting
   - On push: only push the current branch; never force-push
   - On edit: ask the user to paste/dictate the revised message, then commit that
   - On cancel: confirm "Nothing committed." and stop

## Supported Commit Types

Conventional Commits / Angular convention:

- **feat:** A new feature
- **fix:** A bug fix
- **docs:** Documentation only changes
- **style:** Changes that do not affect the meaning of the code
- **refactor:** A code change that neither fixes a bug nor adds a feature
- **perf:** A code change that improves performance
- **test:** Adding missing tests or correcting existing tests
- **build:** Changes that affect the build system or external dependencies
- **ci:** Changes to CI configuration files and scripts
- **chore:** Other changes that don't modify src or test files
- **revert:** Reverts a previous commit

## Examples

### Feature Addition

```
feat: add user authentication system

- Implement JWT token validation
- Add login/logout endpoints
```

### Bug Fix with Scope

```
fix(api): correct user validation logic

- Fix email validation regex pattern
- Update password requirements check
```

## Critical Requirements

**CRITICAL REQUIREMENT**: This commit generator must NEVER add "BREAKING CHANGE" in commit messages under any circumstances.

- Do NOT include "BREAKING CHANGE:" footer text in any generated commit messages
- Do NOT add breaking change notifications or warnings to commit body
- Do NOT use the "!" suffix to indicate breaking changes in commit type
- Do NOT generate breaking change examples or templates

**CRITICAL REQUIREMENT**: Generated commit messages must NOT include any AI attribution, credits, or "generated by" messages.

- Do NOT include "Generated by Claude" or similar AI attribution text
- Do NOT add "Co-Authored-By: Claude <noreply@anthropic.com>" or any AI co-author credits
- Do NOT use emojis like 🤖 or any other AI-related symbols
- Do NOT include references to AI assistance in any form
- Do NOT add "Generated with [Claude Code]" links or similar attribution
- Commit messages must appear as normal human-written commits without any indication of AI involvement

**CRITICAL REQUIREMENT**: Never bypass git safety.

- Never use `--no-verify` to skip hooks
- Never force-push (`--force` / `-f`) on push step
- Never `git add` files automatically — only operate on what the user already staged
